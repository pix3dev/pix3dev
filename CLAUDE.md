# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Pix3 is the marketing landing page for a WebGL 3D playable-ads engine. It is a static site built with Vite + Tailwind v4 and deployed to GitHub Pages on push to `main` via [.github/workflows/static.yml](.github/workflows/static.yml). There is also a more verbose human-facing guide in [AGENTS.md](AGENTS.md).

## Commands

```bash
npm run generate # regenerate src/index.html + src/ru/index.html from generate-pages.js
npm run dev      # Vite dev server (runs generate first via predev)
npm run build    # builds to dist/ (this is what GitHub Pages serves; prebuild runs generate)
npm run preview  # preview the built dist/ locally
node convert-images.js  # one-off: regenerate .webp variants for every .jpg/.png in public/media/
```

There is **no test suite** — `npm test` exits with an error placeholder. Don't add tests unless asked.

## The pages are generated — never hand-edit the HTML (non-obvious)

`src/index.html` and `src/ru/index.html` are **build artifacts** of [generate-pages.js](generate-pages.js), regenerated by `predev`/`prebuild`. Editing them by hand looks like it works in the editor and is silently overwritten on the next `npm run dev`/`build`. All markup changes go into `renderPage()`; all copy goes into the `strings` dictionary.

That one file holds four things:

- **`SITE`** — every outbound URL, the GitHub star count, the demo YouTube id, the Metrika counter id. Links live here, never inline in the template.
- **`strings`** — `en` is the complete reference dictionary; every other locale holds only overrides and is deep-merged onto `en` by `withFallback()`. A missing or untranslated key therefore renders **English, not an empty string**. Keep the key shape identical across locales; arrays are replaced wholesale, not merged element-wise. Locale-invariant technical strings (network names, `player-controller.ts`, `FPS`) are deliberately left out of `ru` so they fall back.
- **`ICONS`** — one stroke set, built by the `stroke()`/`solid()` helpers. All `currentColor`, `aria-hidden`, sized by argument. No colour literals inside SVG markup, no emoji as UI icons.
- **Component helpers** — `btn()`, `ghost()`, `eyebrow()`, `sectionHead()`, `picture()`, `logo()`, `langSwitcher()`. Reuse them instead of pasting markup; `picture()` in particular is what keeps every image sized (`width`/`height`) and lazy below the fold, which is why CLS is 0.

`FOOTER_HREFS` pairs positionally with the translated footer label arrays — if you add a footer link, add it to **both** the labels (in every locale) and the href array.

## Build layout (non-obvious)

[vite.config.js](vite.config.js) sets `root: 'src'`, `publicDir: '../public'`, `base: './'`, `outDir: '../dist'`. Practical implications:

- Edit CSS in `src/`; edit HTML through `generate-pages.js` (above), not the repo root.
- Static assets live in `public/` and are served from the site root at runtime. Inside HTML, reference media as relative paths (`media/icon.webp`) so Vite rewrites them; reference fonts as absolute (`/fonts/ibmplexsans-latin.woff2`) — this is what [src/style.css](src/style.css) already does. (Vite rewrites those absolute paths to `../fonts/…` relative to the emitted CSS, which resolves correctly from both `/` and `/ru/`.)
- `base: './'` makes built asset URLs relative, which is why the site works at any GitHub Pages subpath.
- `package.json` declares `"type": "commonjs"`, but `vite.config.js` uses ESM `import` — Vite handles this; do not "fix" it.

## Styling system

The site follows the "Pix3 Landing v2" design: dark theme only, one accent, sections separated by background steps and 1px lines rather than shadows. [src/style.css](src/style.css) is the whole stylesheet — tokens first, then a semantic component layer (`.btn`, `.card`, `.eyebrow`, `.head`, `.step`, `.bento`, `.band` …). The markup uses those class names, not Tailwind utilities; Tailwind v4 is still imported for preflight and stays available.

Tokens are declared **once**, in the `@theme { ... }` block, and are the only place a colour may be written:

- Every token is `oklch()` and namespaced for Tailwind (`--color-bg`, `--color-fg2`, `--color-amber`, `--font-d`, `--radius-card`, `--container-page`), then aliased on `:root` to the short names the components use (`--bg`, `--fg2`, `--amber`, `--ff-d`, `--r`, `--maxw`).
- **No hex/rgb/oklch literal may appear in a component rule.** Translucent variants are derived with `color-mix(in oklab, var(--token) N%, transparent)` and stored as their own `:root` token (`--amber-ring`, `--glass`, `--shadow-frame`, `--scrim` …). Add a derived token rather than inlining a mix.
- Accent discipline: `--amber` is the only accent fill on the page and belongs to the primary button (which is also the only element with a shadow, along with floating chips/popovers). `--mint` is secondary and reserved for the Developer Experience and Coming Soon eyebrows plus "validated" markers. `--amber-d` is the logo gradient's second stop and the tag colour.
- Ink used *on* amber has its own tokens (`--amber-ink`, `--amber-ink-2`) — never reuse `--bg`/`--fg` there. Measured contrast: `--fg` on `--bg` 17.8:1, `--fg2` on `--bg` 9.7:1, `--amber-ink` on `--amber` 10:1.
- Fonts, self-hosted in `public/fonts/` as variable WOFF2 subsets: `--ff-d` Space Grotesk (headings, buttons), `--ff-b` IBM Plex Sans (body), `--ff-m` JetBrains Mono (eyebrows, labels, numbers). Every face is `font-display: swap`, split by `unicode-range` into latin / latin-ext / cyrillic. **Space Grotesk has no Cyrillic**, so `--ff-d` intentionally falls back to IBM Plex Sans — that is what renders Russian headings. The `/ru/` page preloads the Cyrillic subset as well (`preloadCyrillic` in the locale config).
- Breakpoints: 1200 (bento → 2 columns), 1080 (hero chips hidden), 900 (two-column sections stack, h1 pinned to the bottom of its clamp, **header collapses into the burger drawer** — the inline nav plus GitHub plus language plus CTA do not fit below this), 640 (single column, full-width CTAs, 20px gutter).
- Motion: sections fade in via `.reveal` + IntersectionObserver, once, ~15% visible. `prefers-reduced-motion: reduce` disables it in both CSS and JS; `.no-js` and `@media print` also force content visible, so the copy is never hidden from a reader, crawler or printer.

## Images

Source images go in `public/media/`. The site serves both `.png/.jpg` and a `.webp` variant via `<picture><source srcset="...webp" type="image/webp"><img src="...png">`. After adding or replacing a raster image, run `node convert-images.js` to regenerate the matching `.webp` (uses `sharp`, quality 85), then commit both files.

## Deployment

Pushing to `main` triggers the Pages workflow which runs `npm ci && npm run build` and uploads `dist/`. There is no staging environment — verify locally with `npm run build && npm run preview` before pushing.
